# hamr framework reference for stackr integration

Reference for implementing phase 0. Derived from reading hamr's source and docs at `github.com/FyrmForge/hamr` (master, as of 2026-04-06). This is a snapshot — verify against the actual hamr source if something looks wrong.

## Package inventory

| Package | Use in stackr | DB-agnostic? |
|---------|--------------|-------------|
| `pkg/server` | Echo wrapper, graceful shutdown, middleware registration | Yes |
| `pkg/auth` | Argon2id password hashing, session management | Yes (interface-based) |
| `pkg/middleware` | Auth, RBAC, CSRF, flash, secure headers, audit, rate limit, CORS | Yes (all callbacks/interfaces) |
| `pkg/ctx` | Type-safe Echo context helpers | Yes |
| `pkg/respond` | HTML/JSON content negotiation, error helpers, pagination | Yes |
| `pkg/htmx` | HX-Request detection, response header helpers | Yes |
| `pkg/logging` | slog wrapper (dev=colored text, prod=JSON) | Yes |
| `pkg/config` | Env var accessors | Yes — **skip, stackr keeps its own YAML config** |
| `pkg/validate` | Form validation helpers | Yes |
| `pkg/db` | Postgres connection pool, migrations | **NO — Postgres-only, skip entirely** |

## Server bootstrap (`pkg/server`)

```go
srv, err := server.New(
    server.WithHost(host),
    server.WithPort(port),
    server.WithDevMode(devMode),
    server.WithMaxBodySize("2M"),
    server.WithTimeout(30*time.Second),
    server.WithStaticDir("static"),       // skip in phase 0
    server.WithMiddleware(middlewares...), // variadic echo.MiddlewareFunc
)
srv.Echo()                    // direct *echo.Echo access
srv.GET/POST/PUT/DELETE/PATCH // register routes
srv.Group(prefix, m...)       // route groups
srv.Start()                   // blocks, handles SIGINT/SIGTERM
srv.Addr()                    // "host:port"
```

## Session auth (`pkg/auth`)

### SessionStore interface (we implement against SQLite)

```go
type SessionStore interface {
    Create(ctx context.Context, s *Session) error
    GetByToken(ctx context.Context, token string) (*Session, error)
    Delete(ctx context.Context, id string) error
    DeleteBySubjectID(ctx context.Context, subjectID string) error
}

// Optional — implement if we want sliding session refresh:
type SessionToucher interface {
    Touch(ctx context.Context, id string, newExpiresAt time.Time) error
}
```

### Session struct

```go
type Session struct {
    ID        string
    SubjectID string
    Token     string      // 32-byte random token (generated by SessionManager)
    ExpiresAt time.Time
    CreatedAt time.Time
    metadata  any         // project-specific, set via CreateSession
}
```

### SessionManager

```go
sessMgr := auth.NewSessionManager(store SessionStore, opts ...SessionOption)

// Options:
auth.WithDuration(7*24*time.Hour)              // default: 7 days
auth.WithCookieName("session_token")           // default
auth.WithCookiePath("/")                       // default
auth.WithCookieDomain(".example.com")          // default: "" (host-scoped)
auth.WithCookieSecure(true)                    // default: true
auth.WithSameSite(http.SameSiteLaxMode)        // default
auth.WithSlidingRefresh(threshold)             // optional, requires SessionToucher

// Methods:
sessMgr.CreateSession(ctx, subjectID string, metadata any) (*Session, error)
sessMgr.ValidateSession(ctx, token string) (*Session, error)  // returns (nil, nil) for expired/not found
sessMgr.DeleteSession(ctx, id string) error
sessMgr.DeleteSubjectSessions(ctx, subjectID string) error

// Cookie config accessors (for building cookies in handlers):
sessMgr.CookieName() string
sessMgr.CookiePath() string
sessMgr.CookieDomain() string
sessMgr.CookieSecure() bool
sessMgr.SameSite() http.SameSite
```

**Important: session cookies are NOT set automatically.** The login handler must build and set the cookie explicitly using the accessor methods above.

## Auth middleware (`pkg/middleware`)

### AuthConfig

```go
type AuthConfig struct {
    SessionManager *auth.SessionManager
    SubjectLoader  SubjectLoader  // optional callback
    LoginRedirect  string         // default: "/login"
    HomeRedirect   string         // default: "/dashboard"
}

type SubjectLoader func(ctx context.Context, subjectID string) (any, error)
```

### Middleware variants

```go
middleware.Auth(cfg)           // API routes: returns 401 on no session
middleware.RequireAuth(cfg)    // Browser routes: redirects to LoginRedirect on no session
middleware.OptionalAuth(cfg)   // Public routes: loads user if session exists, passes through otherwise
middleware.RequireNotAuth(cfg) // Login page: redirects to HomeRedirect if already logged in
```

### Subject access in handlers

```go
middleware.GetSubjectID(c echo.Context) string   // always set if auth middleware ran
middleware.GetSubject(c echo.Context) any         // set only if SubjectLoader is configured
// Or via ctx package:
ctx.Get(c, ctx.SubjectIDKey)   // (string, bool)
ctx.Get(c, ctx.SubjectKey)     // (any, bool)
```

## RBAC (`pkg/middleware`)

```go
type RoleChecker func(subject any, roles []string) bool
type ActiveChecker func(subject any) bool

middleware.RequireRoles(checker RoleChecker, roles ...string) echo.MiddlewareFunc
middleware.RequireActive(checker ActiveChecker) echo.MiddlewareFunc
```

Callbacks receive the loaded subject from `SubjectLoader`. If `SubjectLoader` is nil, subject is nil and checkers will fail. RBAC requires a real `SubjectLoader` — not relevant until phase 1.

## Content negotiation (`pkg/respond`)

```go
respond.HTML(c echo.Context, status int, component templ.Component) error
respond.JSON(c echo.Context, status int, data any) error
respond.Error(c echo.Context, status int, msg string, component ...templ.Component) error
respond.Redirect(c echo.Context, url string) error  // HTMX-aware: HX-Redirect for HTMX, 303 for browser
respond.ValidationError(c echo.Context, fields map[string]string, component ...templ.Component) error
respond.ParsePagination(c echo.Context, defaultSize int) (page, size int)
```

Format detection: checks `HX-Request` header first (→ HTML), then `Accept` header, then defaults to JSON.

### Idiomatic handler pattern

```go
func (h *Handler) GetItems(c echo.Context) error {
    items, err := h.repo.List(c.Request().Context())
    if err != nil {
        return respond.Error(c, 500, "Failed to load items")
    }
    if htmx.IsHTMX(c.Request()) {
        return respond.HTML(c, 200, components.ItemList(items))
    }
    return respond.JSON(c, 200, items)
}
```

## Other middleware

- `middleware.Secure()` — security headers (X-Frame-Options, CSP, etc.)
- `middleware.CSRF()` / `middleware.CSRFWithConfig(cfg)` — CSRF token via cookie + form/header lookup
- `middleware.SetFlash(c, msg, typ)` — one-time flash messages via cookies
- `middleware.RateLimit(cfg)` — rate limiting
- `middleware.CORS(cfg)` — CORS
- `middleware.Audit(logger AuditLogger)` — audit logging, requires `AuditLogger` interface impl

All are DB-agnostic. Audit takes an `AuditLogger` interface (one method: `Log(ctx, *AuditEntry) error`).

## Login/logout handler patterns

### Login (from hamr docs)

```go
func (h *AuthHandler) PostLogin(c echo.Context) error {
    user, err := h.repo.GetByEmail(c.Request().Context(), c.FormValue("email"))
    if err != nil || user == nil {
        return respond.Error(c, 401, "Invalid credentials")
    }
    ok, err := auth.CheckPassword(c.FormValue("password"), user.PasswordHash)
    if err != nil || !ok {
        return respond.Error(c, 401, "Invalid credentials")
    }
    session, err := h.sessMgr.CreateSession(c.Request().Context(), user.ID, user)
    if err != nil {
        return respond.Error(c, 500, "Failed to create session")
    }
    c.SetCookie(&http.Cookie{
        Name:     h.sessMgr.CookieName(),
        Value:    session.Token,
        Path:     h.sessMgr.CookiePath(),
        Domain:   h.sessMgr.CookieDomain(),
        MaxAge:   int(h.sessMgr.Duration.Seconds()),
        HttpOnly: true,
        Secure:   h.sessMgr.CookieSecure(),
        SameSite: h.sessMgr.SameSite(),
    })
    return respond.Redirect(c, "/dashboard")
}
```

### Logout

```go
func (h *AuthHandler) PostLogout(c echo.Context) error {
    subjectID := middleware.GetSubjectID(c)
    if subjectID != "" {
        h.sessMgr.DeleteSubjectSessions(c.Request().Context(), subjectID)
    }
    c.SetCookie(&http.Cookie{
        Name:   h.sessMgr.CookieName(),
        MaxAge: -1,
    })
    return respond.Redirect(c, "/login")
}
```

## Known documentation gaps in hamr

1. SubjectLoader return type is `any` — you must cast in handlers via `middleware.GetSubject(c).(*User)`.
2. SessionMetadata generic helper signature not documented clearly.
3. Middleware ordering requirements not explicitly documented (logging first, CSRF before flash is assumed).
4. Sliding refresh `Touch()` invocation conditions unclear — validate by reading `SessionManager.ValidateSession` source.
5. Custom error handler integration with content negotiation not documented.
